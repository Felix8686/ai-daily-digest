## ⚡ 行业异动：新模型 · 降价 · 羊毛福利 · 接口预警

**[OpenAI 跟上 Anthropic：$100/$200/$500 订阅档位直接送等额 API 额度](https://simonwillison.net/2026/Oct/29/api-credits/)** (来源: Simon Willison's Weblog)

这是今天唯一真正的福利。ChatGPT 的 $100/$200/$500 订阅用户，可以拿到等额的 API credits（**有有效期，会过期**）。Anthropic 本月初刚给 Max/Team 用户发了同样的东西，OpenAI 直接照抄。

- **对你的实际影响**：如果你已经在 $200 档，等于每月白拿 $200 的 API 预算，可以直接用在 Hermes 的批处理脚本上跑长任务（批量摘要、批量打标、批量转写），不用再从个人卡里扣钱。
- **别做的事**：不要因为有额度就无脑跑大模型。额度过期作废，按“本月要跑完的活”来排，而不是“先囤着”。

- **真正的价值在价格**：权重一旦公开，Together / Fireworks / OpenRouter 这类第三方推理商几周内就会把价格打下来。如果你现在用闭源模型跑 coding agent，下个月可以重新比一次价，API 成本大概率还能再降一档。

## 💻 本地平替与上手神器

**[Liquid AI 发布 LFM3：六个 2B 开源小模型，单卡可微调，覆盖文本/视觉/音频/决策](https://alphasignal.ai/news/liquid-ai-s-lfm3-beats-9b-rivals-using-a-tiny-1-7b-on-device-model)** (来源: AlphaSignal)

这是端侧小模型家族，不是单点模型，而且文本、视觉、音频、omni 四类都覆盖了，权重全开、单 GPU 就能微调。

- **能帮你省什么**：离线语音转文字的前置降噪分类、本地 OCR 后的字段抽取、Hermes 里那些“不值得调云端 API”的意图判断，都可以挪到本地跑，零成本、零延迟、数据不出机器。
- **注意**：“1.7B 打败 9B”这句先打个折，理由见下面第四板块。

## 🎯 创作者风控与爆款选题

**[Flatbread：分享“整个 Agent 运行过程”，而不是一张截图](https://www.producthunt.com/products/flatbread)** (来源: Product Hunt)

Agent 类内容最大的信任问题是：你说它跑通了，但没人看得见过程。Flatbread 干的事就是把一次完整 run 的每一步、每次工具调用、每个中间产物打包成可分享的页面。

- **【写作切入点建议】**：不要写工具测评，写成实操复盘。标题方向“我把 Agent 干活的全程录下来了，每一步都能查”。用一次真实的「Hermes 自动整理 Obsidian 收件箱」做样本，把失败的两步也放出来，这比任何一张漂亮的九宫格截图都更有说服力，也是你区别于搬运号的护城河。

**[有人做了个“全 AI 驱动”的多人游戏世界，玩家用 prompt 改游戏规则](https://simonwillison.net/2026/Oct/29/how-i-built-the-most-ai-pilled-company-in-the-world/)** (来源: Simon Willison's Weblog)

Spawn 这个项目里，玩家对游戏内 agent 下 prompt，就能改玩法、加内容、动机制，本质上是把“改代码的权限”交给了自然语言。

- **【写作切入点建议】**：别写成“AI 游戏评测”，那没人看。写成普通人的实测打假——“当产品把改代码权限交给用户的 prompt，它能撑多久才崩？”实测 30 分钟，重点记录它把机制改崩的那一瞬间，以及失控之后谁来兜底。这个角度，你读者里的产品经理和独立开发者会转。

## 🔍 暗改排雷与避坑打假

**[“小模型吊打大模型”的榜单话术，先打五折再看](https://simonwillison.net/2026/Oct/28/ted-sanders/)** (来源: Simon Willison's Weblog)

今天 LFM3 主打“1.7B 打败 9B”，同一天就有人把底层逻辑说清楚了：LLM 的性能确实是多维的，但**绝大部分差异只由一个变量解释——模型规模**。模型越大，越可靠，也越贵。

- **怎么排雷**：看到“小模型吊打大模型”，先问三个问题：① 榜单是不是自家挑的？② 任务是窄领域单轮问答，还是长上下文 + 多轮工具调用？③ 指令遵循的**稳定性**测了吗？
- **能帮你省什么**：省你一晚上。小模型在窄任务（分类、抽取、短转写）上确实够用，值得本地部署；但你那套 Hermes 里多步串联、需要严格 JSON 输出的链路，换成小模型后第一周的错误率上升，会全部算在你头上。**窄任务换小模型省钱，主链路别动。**
